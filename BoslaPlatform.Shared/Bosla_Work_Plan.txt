1. Onion Architecture Overview
Bosla uses Onion Architecture with 5 projects. Business logic lives in Services inside Application —
MediatR is used only for Domain Events (INotification) and Pipeline Behaviours. The Result<T> pattern handles expected failures without exceptions.

Project	Role	Depends On
Bosla.Domain	Entities, Enums, Value Objects, Domain Events, Result<T>, Error. Zero dependencies.	Nothing
Bosla.Shared	Result<T>, Error, ErrorKind, Pagination, Constants, Helpers. Used everywhere.	Nothing
Bosla.Application	Service interfaces (Abstractions), Feature Services, DTOs, Validators, Behaviours, Mappings.	Domain + Shared
Bosla.Infrastructure	EF Core, Identity, Interceptors, Repositories, AI clients, Background Jobs, Observability.	Application
Bosla.API	Controllers (V1), Middleware, Filters, Swagger, DI wiring. Entry point.	Application + Infrastructure

ℹ  Dependency Rule: API → Application → Domain. Infrastructure → Application.
    Bosla.Shared has no project references — it is referenced by all layers.
    - Controllers call IXxxService directly via constructor injection.
    MediatR used ONLY for Domain Events (INotificationHandler) and Pipeline Behaviours.

// Bosla.Shared/Results/ErrorKind.cs
public enum ErrorKind
{
    None, NotFound, Validation,Forbidden, BadRequest, Unexpected,
    Conflict, Unauthorized, Failure
}

// Bosla.Shared/Results/Error.cs
    public readonly record struct Error
    {
        private Error(string code, string description, ErrorKind type)
        {
            Code = code;
            Description = description;
            Type = type;
        }

        public string Code { get; }

        public string Description { get; }

        public ErrorKind Type { get; }

        public static Error Failure(string code = nameof(Failure), string description = "General failure.")
            => new(code, description, ErrorKind.Failure);

        public static Error Unexpected(string code = nameof(Unexpected), string description = "Unexpected error.")
            => new(code, description, ErrorKind.Unexpected);

        public static Error Validation(string code = nameof(Validation), string description = "Validation error")
            => new(code, description, ErrorKind.Validation);

        public static Error Conflict(string code = nameof(Conflict), string description = "Conflict error")
            => new(code, description, ErrorKind.Conflict);

        public static Error NotFound(string code = nameof(NotFound), string description = "Not found error")
            => new(code, description, ErrorKind.NotFound);

        public static Error Unauthorized(string code = nameof(Unauthorized), string description = "Unauthorized error")
            => new(code, description, ErrorKind.Unauthorized);

        public static Error Forbidden(string code = nameof(Forbidden), string description = "Forbidden error")
            => new(code, description, ErrorKind.Forbidden);

        public static Error Create(ErrorKind type, string code, string description)
            => new(code, description, type);
    }

// Bosla.Shared/Results/Result.cs
    public sealed class Result<TValue>
        : Result, IResult<TValue>
    {
        private readonly TValue? _value;

        public TValue Value =>
            IsSuccess
                ? _value!
                : throw new InvalidOperationException(
                    "Cannot access value of failed result.");

        private Result(TValue value)
            : base(true)
        {
            _value = value;
        }

        private Result(List<Error> errors)
            : base(false, errors)
        {
        }

        public static Result<TValue> Success(TValue value)
            => new(value);

        public static Result<TValue> Failure(Error error)
            => new([error]);

        public static Result<TValue> Failure(List<Error> errors)
            => new(errors);

        public TResult Match<TResult>(
            Func<TValue, TResult> onSuccess,
            Func<IReadOnlyList<Error>, TResult> onFailure)
        {
            return IsSuccess
                ? onSuccess(Value)
                : onFailure(Errors);
        }

        public static implicit operator Result<TValue>(TValue value)
            => Success(value);

        public static implicit operator Result<TValue>(Error error)
            => Failure(error);

        public static implicit operator Result<TValue>(List<Error> errors)
            => Failure(errors);
    }

3.4  MediatR — Domain Events Only
MediatR is NOT used for request handling. It is used ONLY to dispatch Domain Events after SaveChanges via DomainEventsInterceptor.

// Bosla.Domain/Events/AppointmentCreatedEvent.cs
public record AppointmentCreatedEvent(Guid AppointmentId) : DomainEvent;

// Bosla.Domain/Entities/Appointment.cs — raises event inside entity
public class Appointment : AuditableEntity
{
    public static Result<Appointment> Schedule(Guid userId, Guid specialistId,
        DateTime startTime, DateTime endTime)
    {
        var appointment = new Appointment { ... };
        appointment.RaiseDomainEvent(new AppointmentCreatedEvent(appointment.Id));
        return appointment;
    }
}

// Bosla.Infrastructure/Data/Interceptors/DomainEventsInterceptor.cs
public class DomainEventsInterceptor(IPublisher publisher) : SaveChangesInterceptor
{
    public override async ValueTask<int> SavedChangesAsync(
        SaveChangesCompletedEventData data, int result, CancellationToken ct)
    {
        var events = data.Context!.ChangeTracker
            .Entries<BaseEntity>()
            .SelectMany(e => e.Entity.DomainEvents)
            .ToList();

        foreach (var e in events) await publisher.Publish(e, ct);
        return result;
    }
}

3.5  MediatR Behaviours Pipeline

Order	Behaviour	Purpose
1	LoggingBehavior	Logs request name + execution time
2	PerformanceBehavior	Warns if execution > 500ms
3	UnhandledExceptionBehavior	Catches and logs unexpected exceptions
4	ValidationBehavior	Runs FluentValidation — returns error if fails
5	CachingBehavior	HybridCache check for cacheable requests

⚠  Behaviours apply to MediatR pipeline — but since Controllers call Services directly (not MediatR Send), Behaviours run only for Domain Event handlers.
    Validation in Controllers is handled via FluentValidation + ValidationFilter in Bosla.API.

3.6  Result → Problem Details (RFC 7807)

// Bosla.API/Common/Extensions/ResultExtensions.cs
        public static class ProblemExtensions
    {
        public static IResult ToProblem(this IReadOnlyList<Error> errors)
        {
            if (errors.Count == 0)
            {
                return Results.Problem();
            }

            if (errors.All(error => error.Type == ErrorKind.Validation))
            {
                return ValidationProblem(errors);
            }

            return Problem(errors[0]);
        }

        private static IResult Problem(Error error)
        {
            var statusCode = error.Type switch
            {
                ErrorKind.Conflict => StatusCodes.Status409Conflict,
                ErrorKind.Validation => StatusCodes.Status400BadRequest,
                ErrorKind.NotFound => StatusCodes.Status404NotFound,
                ErrorKind.Unauthorized => StatusCodes.Status403Forbidden,
                _ => StatusCodes.Status500InternalServerError,
            };

            return Results.Problem(statusCode: statusCode, title: error.Description);
        }

        private static IResult ValidationProblem(IReadOnlyList<Error> errors)
        {
            var errorsDict = errors.ToDictionary(e => e.Code, e => new[] { e.Description });

            var problemDetails = new ValidationProblemDetails(errorsDict)
            {
                Status = StatusCodes.Status400BadRequest
            };

            return Results.Json(problemDetails, statusCode: StatusCodes.Status400BadRequest);
        }
    }
3.7  Hybrid Caching — HybridCache + Output Cache

// Inside a Service method — HybridCache for data
public async Task<Result<List<SpecialistDto>>> GetSpecialistsAsync(
    GetSpecialistsRequest request, CancellationToken ct)
{
    return await _cache.GetOrCreateAsync(
        $"{CacheKeys.Specialists}:{request.Page}:{request.Filter}",
        async token => await FetchFromDb(request, token),
        new HybridCacheEntryOptions
        {
            Expiration = TimeSpan.FromMinutes(5),
            LocalCacheExpiration = TimeSpan.FromMinutes(1)
        }, cancellationToken: ct);
}

3.8  DI Extension Methods

// Bosla.Application/DependencyInjection.cs
public static IServiceCollection AddApplication(this IServiceCollection services)
{
    services.AddMediatR(cfg =>
        cfg.RegisterServicesFromAssembly(Assembly.GetExecutingAssembly()));

    services.AddValidatorsFromAssembly(Assembly.GetExecutingAssembly());
    services.AddAutoMapper(Assembly.GetExecutingAssembly());

    services.AddTransient(typeof(IPipelineBehavior<,>), typeof(LoggingBehavior<,>));
    services.AddTransient(typeof(IPipelineBehavior<,>), typeof(PerformanceBehavior<,>));
    services.AddTransient(typeof(IPipelineBehavior<,>), typeof(UnhandledExceptionBehavior<,>));
    services.AddTransient(typeof(IPipelineBehavior<,>), typeof(ValidationBehavior<,>));
    services.AddTransient(typeof(IPipelineBehavior<,>), typeof(CachingBehavior<,>));

    return services;
}

// Bosla.Infrastructure/DependencyInjection.cs
public static IServiceCollection AddInfrastructure(
    this IServiceCollection services, IConfiguration config)
{
    services.AddDbContext<ApplicationDbContext>((sp, o) => o
        .UseSqlServer(config.GetConnectionString("DefaultConnection"))
        .AddInterceptors(
            sp.GetRequiredService<AuditableEntityInterceptor>(),
            sp.GetRequiredService<DomainEventsInterceptor>()));

    services.AddScoped<IApplicationDbContext>(
        sp => sp.GetRequiredService<ApplicationDbContext>());

    services.AddHybridCache();
    services.AddStackExchangeRedisCache(o =>
        o.Configuration = config["Redis:ConnectionString"]);

    // AI Provider switching
    var provider = config["AI:Provider"];
    services.AddScoped<IEmbeddingService>(_ =>
        provider == "Claude"
            ? new ClaudeEmbeddingService(config)
            : new OpenAiEmbeddingService(config));

    services.AddHangfire(o =>
        o.UseSqlServerStorage(config.GetConnectionString("DefaultConnection")));

    return services;
}

8. Coding Standards
8.1  Naming
Item	Convention	Example
Service interface	I + PascalCase + Service	IAppointmentService
Service implementation	PascalCase + Service	AppointmentService
Request DTO	PascalCase + Request	CreateAppointmentRequest
Response DTO	PascalCase + Response / Dto	AppointmentDto
Domain Event	PascalCase + Event	AppointmentCreatedEvent
Event Handler	Verb + On + EventName	CreateRemindersOnAppointmentCreated
Background Job	PascalCase + Job	EmbeddingRebuildJob
Error code	Entity.Issue	Appointment.NotFound
Endpoint route	lowercase kebab-case plural, versioned	/api/v1/video-sessions
Controller	PascalCase + Controller in V1 folder	AppointmentsController

8.2  Non-Negotiable Rules
⦁	Every Service method returns Result<T> — no exceptions for expected failures
⦁	Every Controller maps Result<T> via .ToActionResult(this) — no raw status codes
⦁	Controllers inject IXxxService only — zero business logic in controllers
⦁	MediatR is for Domain Events only — do NOT use _mediator.Send() for HTTP requests
⦁	Domain Events raised inside entity factory/action methods — not in services
⦁	Every Appointment status change → INSERT AppointmentStatusHistory in same transaction
⦁	Every Admin write operation → call IAuditLogService.RecordAsync() in same transaction
⦁	Every Specialist profile/experience/skill write → raise SpecialistProfileUpdatedEvent
⦁	Program to IEmbeddingService / IVectorStore / IChatService — never concrete AI types
⦁	All LLM calls have timeout (30s) + retry with Polly (3 attempts, exponential backoff)
⦁	RTC Token generated per-request server-side — never stored in DB
⦁	All datetime stored and returned as UTC
⦁	Soft delete via AuditableEntityInterceptor — never hard delete Users, Specialists, Appointments
⦁	All endpoints versioned under /api/v1/ — V2 folder ready for future
⦁	FluentValidation for all Request DTOs — ValidationFilter handles response
⦁	Architecture Tests enforce layer dependency rules — CI fails if violated
⦁	PR requires at least 1 reviewer approval before merge to develop
